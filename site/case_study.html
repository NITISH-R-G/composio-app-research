The agent: what actually did the research

Ten parallel research agents, one per category, each with real web search and a strict cited-JSON schema. An eleventh agent independently re-derived a sample to check the first pass's work.

01

100-app list → 10 category batches

data/apps.json splits the assignment's list into 10 groups of 10 by category (CRM, Support, Comms, ... AI).

→
02

10 parallel research agents

Each agent gets a strict prompt (agent/schema.py) — auth, self-serve, API surface, MCP, verdict, blocker — and must cite a real docs URL for every claim, or say "low confidence" instead of guessing.

→
03

Merge → 100-record dataset

Structured JSON outputs are validated against the schema and merged into data/results.json.

→
04

Independent verification agent

A blind 11th agent re-researches an 18-app sample from scratch and diffs against the first pass — see agent/verify.py for the same loop, runnable on the full 100.

Where a human is needed: 6 of 100 apps came back confidence: low because the agent genuinely could not find public docs (fanbasis, Paygent Connect) or found only thin/unverifiable sources (MrScraper, Waterfall.io, higgsfield). That's the correct output — the agent flagged its own uncertainty rather than fabricating an answer — but confirming these apps truly have no path in requires a human to sign up, email sales, or dig through a password-gated portal directly. MCP existence is also the single most volatile field: it decays within weeks as vendors ship new official servers, so anything below "high" confidence there is a lead to re-check, not a final answer.

Verification: what was actually checked, and how

An independent agent, blind to the first pass's reasoning, re-researched 18 of the 100 apps from scratch and diffed the answers field-by-field across 4 fields — 72 field-checks in total. Corrections were then merged back into the dataset.

Sample: 18 / 100 apps

Scope, stated precisely: this measures 4 fields (auth method, self-serve status, MCP existence, buildability verdict) across an 18-app sample — 72 field-checks. It is not a claim that all 100 records are verified; the other 82 apps carry only their first-pass confidence rating. The second pass re-researched each app independently rather than hand-checking every claim against first-party docs, so some corrections rest on credible secondary sources — each one is linked in the verification log.

Built for the Composio primary-filter assignment. Research executed as 10 parallel Claude Code subagents with real web search against live developer docs, then independently re-researched by an 11th agent on an 18-app sample; see the README for how to re-run the same pipeline directly against the Anthropic API. The reusable pipeline is structured LLM research + web search with a strict cited-JSON schema; a Composio API key is optional and used only to cross-check apps against Composio's own toolkit registry.
