02The access ladder

API availability is not the bottleneck. Access is.

__LADDER__

Rungs derived from the dataset: api_surface is a real hosted API; auth_method is known; self_serve is free or trial; verdict is “buildable today”.

OAuth2 dominates, but rarely alone

63 of 100 support OAuth2 — yet 49 of those also offer an API key or Basic-auth path, so a working integration seldom requires building a full OAuth flow first.

“Self-serve” hides a second gate

54 are free forever. Another 22 self-signup onto a time-limited trial — and four carry a gate the pricing page omits: Lark needs tenant-admin approval, Threads needs Meta App Review, Neo4j wants billing details, Squarespace requires a paid Commerce plan.

Friction clusters by category

Finance and AI-native tools carry the most limited or blocked verdicts — KYC, business verification, and enterprise contracts sit in front of the docs. Support and Developer/Infra are the cleanest.

03Recommendation

What should Composio build first?

Sorted by access friction rather than category. Every app lands in exactly one tier; the tiers sum to 100.

__TIERS__

A caution on MCP. MCP availability was the most error-prone field in this research. It is a useful ecosystem signal — it says a vendor already invests in agent access — but it is not a substitute for API feasibility and should not be the primary buildability criterion. The order that matters: can we access the product, can we authenticate, is the API useful enough, is it commercially viable, and only then, does an MCP server already exist.

06Where it failed

The agent was wrong 5 times.

Never a fabricated verdict — each was one stale or overstated field. The errors clustered in two places, and those are the two fields any agent working this problem will keep getting wrong.

Scope, stated precisely. This measures four fields — auth method, self-serve status, MCP existence, buildability verdict — across an 18-app sample. It is not a claim that all 100 records are verified; the other 82 carry only their first-pass confidence rating. The second pass independently re-researched each sampled app rather than hand-checking every claim against first-party documentation, so some corrections rest on credible secondary sources. Each one is linked in data/verification.json.
