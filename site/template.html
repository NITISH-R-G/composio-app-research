Research pipeline

How was the research done?

Takes a list of apps, researches each one against live documentation, produces structured records with evidence, and runs an independent verification pass over a sample. The 100-app list is one input; swap data/apps.json to point it at a different set.

  1. 10 category batches. The 100-app list split by category. A failed batch can be rerun without touching the other nine.
  2. 10 research workers, run in parallel. Each searched developer documentation, authentication pages, pricing and access pages, and MCP references, then filled a fixed schema. A worker that couldn't establish an answer returned low confidence instead of guessing.
  3. 100 structured records, validated against the schema and merged into data/results.json.
  4. Independent re-research of 18 apps by a separate worker with no access to the first pass's answers.
  5. Field-by-field comparison on four decision-relevant fields per app: 72 checks.
  6. Corrections merged back into the dataset after checking against sources.

Each record must supply auth_method, self_serve, api_surface, mcp_exists, buildability_verdict, evidence, and confidence. The prompt requires a source URL for every claim; output that doesn't parse as valid JSON against these keys is retried once, then recorded as a parse error.

Run it yourself

The pipeline runs against any app list. These are the actual commands, from the repository root.

pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...

# smoke test against 5 apps
python agent/research.py --input data/apps.json --output data/results.json --limit 5

# full run over the 100-app list
python agent/research.py --input data/apps.json --output data/results.json

# independent verification pass over a random sample
python agent/verify.py --input data/results.json --sample 20 --output data/verification.json
