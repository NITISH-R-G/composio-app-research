One caution on MCP. MCP availability was the single most error-prone field in this research, and it is a useful ecosystem signal — it says a vendor is already investing in agent access. It is not a substitute for API feasibility, and it shouldn't be the primary buildability criterion. The order that actually matters is: can we access the product → can we authenticate → is the API useful enough → is it commercially viable → and only then, does an MCP server already exist.

The agent: what actually did the research

Ten parallel research agents, one per category, each with real web search and a strict cited-JSON schema. An eleventh agent independently re-derived a sample to check the first pass's work.

Independent verification agent

A blind 11th agent re-researches an 18-app sample from scratch and diffs against the first pass — see agent/verify.py for the same loop, runnable on the full 100.

Where a human is needed: 6 of 100 apps came back confidence: low because the agent genuinely could not find public docs (fanbasis, Paygent Connect) or found only thin/unverifiable sources (MrScraper, Waterfall.io, higgsfield). That's the correct output — the agent flagged its own uncertainty rather than fabricating an answer — but confirming these apps truly have no path in requires a human to sign up, email sales, or dig through a password-gated portal directly. MCP existence is also the single most volatile field: it decays within weeks as vendors ship new official servers, so anything below "high" confidence there is a lead to re-check, not a final answer.

Verification: what was actually checked, and how

An independent agent, blind to the first pass's reasoning, re-researched 18 of the 100 apps from scratch and diffed the answers field-by-field across 4 fields — 72 field-checks in total. Corrections were then merged back into the dataset.
