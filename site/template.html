Research pipeline

How was the research done?

Takes a list of apps, researches each against live documentation, produces structured records with evidence, and independently re-researches a sample. The 100-app list is one input; swap data/apps.json to point it at a different set.

Input
100 apps, 10 categories: data/apps.json
Research
10 parallel category workers, each searching developer docs, auth pages, pricing/access pages, and MCP references
Structure
100 schema-constrained records: data/results.json
Verify
18-app independent sample, 72 field comparisons, no access to the first pass's answers
Correct
5 source-checked corrections merged back into the dataset
Output
results.json + verification.json
  1. Each category batch can be rerun on its own without touching the other nine.
  2. A worker that can't establish an answer returns low confidence instead of guessing.
  3. Every record supplies auth_method, self_serve, api_surface, mcp_exists, buildability_verdict, evidence, and confidence. The prompt requires a source URL for every claim; output that fails to parse against these keys is retried once, then recorded as a parse error.

Run it yourself

pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...

# smoke test against 5 apps
python agent/research.py --input data/apps.json --output data/results.json --limit 5

# full run over the 100-app list
python agent/research.py --input data/apps.json --output data/results.json

# independent verification pass over a random sample
python agent/verify.py --input data/results.json --sample 20 --output data/verification.json
